These are valid derivations, optional refinements or declared evidence gaps, rather than confirmed defects merely because spellings differ. Final lifecycle constraints, including exactly 20%/50% on issued quotations and immutable accepted manufacturing/payment records, remain gated where authentic historical values or later writer compatibility are required.

Order/client carriers in composite FKs enforce ownership; they are not arbitrary duplication. PO derives client through inquiry; invoice derives PO/client through the existing one-PO/one-invoice-per-inquiry keys. A JO stores PO, accepted quote, inquiry and client together **with composite consistency FKs** because its items must prove the same accepted source. Delivery stores JO + inquiry with one composite FK and derives client/PO/invoice, avoiding four independent contradictory relationships.

Quote references/revisions, frozen quote BOM names/prices/units, order requests, replacement requests, pricing add-ons/discounts, typed file links, recipient states and accepted signed-DR slots have legitimate purposes. Do not delete them because absent from the simplified drawing. Preserve `material_import_review` as reconciliation evidence. No costing/BOM import or catalog population is included.

The existing minimum inquiry quantity is retained. JO items use positive whole-piece quantities, not that inquiry minimum, because a manufacturing allocation is not a new inquiry. Raw-material values remain DECIMAL(15,4), money DECIMAL(15,2), rates their existing precision, timestamps DATETIME(3). IDs remain unsigned BIGINT and API consumers must retain decimal strings. Existing textual dimensions are retained for all six templates; converting undocumented units/free text into numeric millimetres would lose information. Snapshot columns intentionally duplicate issue-time facts; updating them from masters would create a historical update anomaly.

E02's wider unique parent keys permit composite ownership FKs on MySQL 8.4 without depending on nonunique referenced keys. E03 indexes target actual ownership/history/queue relationships. No speculative broad dashboard indexes are added: plans/volumes must justify them. Per-parent mandatory *one-or-more* items, stage sequencing, delivered-total limits, immutable snapshots, employee authorization and accepted-receipt-before-transaction are transaction/authorization invariants, not established by a simple FK or CHECK.

## Inventory consistency and cutover contract

**E03 is not an active ledger correction by itself.** It must not be used alongside balance writers that omit it. Until a later compatibility task is approved and accepted, current audited writes retain their existing behavior; target tables stay inactive. The known D05 completeness defect remains open, not cured by adding a table.

The future authorized writer must lock the inventory parent, read number and provenance in that transaction, validate the canonical unit, and append exactly one movement with the balance/status update and audit. A verified old balance permits an arithmetic delta. Unknown/sample old stock permits an observation of the new verified balance with NULL before/delta; the first count is not a receipt from imaginary zero. Same-value sample verification must append observation evidence; a verified no-op follows Q02 semantics. Duplicate operation keys return the original committed result; competing keys serialize on the same item. Failure of any statement rolls back all writes. Lock both item and JO ownership where relevant. No quotation/read/JO creation initiates stock changes.

Before activation, approve enforcement against bypassing the writer (restricted procedure-only grants or an equally reviewed database write boundary), then test failure/concurrency/read-back. No grants/procedures/triggers have been changed here. Existing FG zero is unverified historical data until observed; do not promote all FG counts on transfer. Explicit FG quantity/threshold provenance expansion requires classification evidence before any default or NOT NULL conversion. Both legacy ledgers remain auditable; generic audit is not converted into synthetic stock movements.
