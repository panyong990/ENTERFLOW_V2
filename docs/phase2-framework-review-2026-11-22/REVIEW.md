## Blockers before live activation

**B1 — Server certificate identity verification is missing.** `database/migrate.mjs:24` requires a CA and rejects the self-signed bypass; line 31 sets `rejectUnauthorized: true`, but does not set or otherwise implement server-identity verification. The installed mysql2 3.24.6 source explicitly reads `ssl.verifyIdentity` in `node_modules/mysql2/lib/base/connection.js:430` and substitutes a no-op identity checker when it is false/undefined at line 450. `connection_config.js:170` defaults chain rejection, not identity verification. Therefore the code requests CA chain validation but does not bind the certificate to the intended server identity. The prior description of "verified TLS" was too broad.

Required disposition: review an identity-verification approach that actually validates the fixed IP endpoint with this driver, including its IP-specific path at `connection.js:431` and `:464`. Merely adding an untested flag is not sufficient evidence. Add offline tests for correct identity configuration and rejection of a CA-valid wrong identity. Do not change the shared profile's TLS behavior. No certificate or credential was opened or created in this review; only installed driver source was read.

**B2 — History is queried before its object type/shape is trusted.** `migration-phase2.mjs:175` recognizes the isolated history object by name alone. Line 177 selects its checksums before line 184 verifies the metadata contract. A view with that name can therefore be queried before the runner rejects it as unexpected; such a view could expose another ledger, contrary to the protected-history boundary. A malformed base table is likewise read before its shape is checked. This is a source-confirmed ordering defect; no such object was inspected live or claimed to exist.

Required disposition: validate the isolated history object as the intended InnoDB base table, with its expected columns/keys and no unexpected behavior, before reading its contents. Retrieve allowed filenames/states first and reject unknown/deferred rows before retrieving checksums. Add a synthetic view fixture whose content query throws if called, plus unknown/deferred-row tests that model retrieval rather than just JavaScript property access.

**B3 — Extension 003 requires an independently enforced exclusive-writer window.** Lines 191 and 204 count applications before the ALTERs, but the advisory lock at line 170 coordinates only participating Phase 2 runners. It does not block registration or unrelated SQL writers. A row inserted after the count and before the second ALTER invalidates the empty-table precondition; a successful count cannot guarantee the prohibition on invented usernames/backfills. The patch has no writer-quiescence enforcement. This is an operational activation blocker, not evidence of existing data damage. Stephanie must review how writers will be excluded for the entire activation window, or approve a framework safeguard before execution. No application was stopped or switched here.

## Required fixes and missing acceptance tests

**R1 — Extension metadata tests need an independent oracle.** In `migration-phase2.test.mjs:45`, the fake database returns metadata generated by the production `phase2ExpectedMetadata` helper. The runner then compares that metadata against the same helper at `migration-phase2.mjs:217`. A shared mistake in generated expressions, defaults, implicit indexes, ordinal positions or CHECK text can pass the success test and then fail after live DDL has already committed. Mutation tests show that differences are detected, but do not independently establish the expected contract. Add independently authored/reviewed metadata fixtures for stages 0/1/2/3 and the isolated history table. An offline fixture remains distinct from later approved MySQL evidence; do not create a database to address this review.

**R2 — Index equivalence currently omits structural fields.** The index projection at `migration-phase2.mjs:61` captures names, columns, order and uniqueness, but not `SUB_PART`, `INDEX_TYPE`, direction, visibility or functional expressions. For example, a shorter prefix index can retain the same captured metadata and pass comparison despite different uniqueness/query behavior. The pinned historical evidence also lacks these fields. Add reviewed Phase 2-specific checks/contract coverage for these properties without altering the protected P2B002 evidence. Tests must include same-name/same-column prefix and visibility mismatches. Current comparison should not be represented as exact structural equivalence in all index properties.

**R3 — Durability and lost-acknowledgement assertions are incomplete.** The double updates the ledger immediately (`test.mjs:71`, `:75`, `:79`); its commit merely increments a counter and its rollback does not model transactional state (`:83`). The test named "commit acknowledgement lost after DDL" fails the second commit, before the completion update, rather than losing the acknowledgement of an applied-state update/commit. The applied-update failure double throws before changing its row, rather than modeling an update that committed but lost its response. Add separate cases for both possible persisted outcomes, inaccessible failure markers after connection loss, final completion-commit acknowledgement loss, history-table creation/verification failure, and applying-marker insert acknowledgement loss. Preserve the rule that any uncertain state stops the current invocation; no automatic DDL retry or manual history forcing.

**R4 — CLI and shared-profile evidence need broader offline coverage.** The CLI routing test replaces `runPhase2` with a stub (`test.mjs:239`); most prerequisite/failure tests call the real core directly. Add a composed CLI-to-real-Phase-2-core test using the isolated fixture directory and a connection double. Cover unsupported Phase 2 commands at the CLI boundary, malformed/reordered/duplicate flags, nonexistent explicit environment files, CA read failure, connect/close errors, the original 3309 allowlist/name rules, and preservation of the original shared dispatch. Test environment-file versus pre-existing process-environment conflicts explicitly: the selected file is loaded into `process.env`, not treated as an independently validated immutable configuration. Do not introduce real credential files. Missing tests are proposed work, not new results.
